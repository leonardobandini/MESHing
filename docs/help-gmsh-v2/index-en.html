MESHing technical guide for meshing SAP2000/CSiBridge areas with Gmsh

MESHing · workflow and meshing parameters.

Operating procedure. Open a saved SAP2000 or CSiBridge model and select the areas to mesh. Generate first creates the optional numbered backup, then saves the current model to its SDB/BDB and creates the mesh in memory. FAST transfer is automatic where supported; there is no Apply step. Inspect the resulting mesh and its quality. Undo mesh restores the model saved immediately before the last Generate. Select another area to enable Generate again: the next Generate warns that it will save the current model, replacing the previous Undo point. Closing MESHing also ends the possibility of Undo; the meshed model remains unsaved, so closing the host model without saving reopens the state on disk from before the last Generate. Keep the numbered backup enabled if the earlier saved state must also be preserved.

Setup and external prerequisite. Extract the ZIP and run MESHingSetup.exe (install_MESHing.cmd opens the same window). The graphical installer presents MESHing, its GPL terms and source references, and every phase: checking open programs, prerequisites, verification, replacing a previous version and registering the SAP2000/CSiBridge menus. If a host is open, it asks you to close it and will not proceed until it exits; no model is closed or saved by the installer. It starts in the Windows display language and lets you switch manually using Lingua / Language. It checks for the official Microsoft Visual C++ Redistributable x64, version 14.42.34226.3 or later compatible. If missing, it downloads the package directly from Microsoft, checks its digital signature and starts Microsoft's interactive setup, including its license terms and UAC prompt. If a restart is required, restart Windows and rerun the MESHing installer. Without network access, install the prerequisite separately using the Microsoft link. Microsoft Visual C++ runtime DLLs are not included in the MESHing package.

Gmsh attribution. MESHing uses Gmsh 4.15.2 and its Python binding to generate the mesh. Gmsh is copyright © C. Geuzaine and J.-F. Remacle and is distributed by its copyright holders under GNU GPL version 2 or later, with its own limited exception. For information, documentation and upstream sources, see the official Gmsh website. The Gmsh license text and copyright notices are included in the MESHing package; the corresponding Gmsh sources are available as an asset of the same release. Choosing GPLv3 for the combined backend does not change Gmsh's original license.

Introduction

MESHing uses CSiAPIv1 and registers Tools > MESHing in already installed SAP2000/CSiBridge versions 27 and later. Meshing and snapshot restoration were verified on disposable SDB/BDB models with version 27, including a test of the 27.2.0 beta of the first host. Final later host releases will be verified when available. The model diagrams come from the SDB catalog; BDB trials were verified separately.

The Plug-in subdivides selected SAP2000/CSiBridge areas into predominantly quadrilateral shell elements using Gmsh. It previews the mesh in the current model and transfers source-area assignments that it can reproduce. Some properties require inspection or reassignment after meshing.

We therefore recommend using the Plug-in early in the modelling process, once the essential geometry is defined and before finalising detailed assignments. Design overwrites, offsets, loads, joint patterns and other project-critical properties can be checked and, where necessary, assigned to the resulting shell areas or joints. See Backup and transfer options for details of what the Plug-in carries over and how the backup works.

Responsibility and model verification. Despite the care taken in developing and testing the Plug-in, the author accepts no responsibility for models modified through its use. Keep the backup option enabled, use a previously saved model and thoroughly inspect the resulting meshed FEM model before using it for analysis or design. When enabled, the backup contains the SDB/BDB file saved before Generate, not changes still in memory. Generate then saves those changes to the active model file; Generate does not save the generated mesh to the active model file.

Reporting problems. Please report errors, malfunctions or inconsistent meshes to leonardo@csi-italia.eu, including the Plug-in version, a description of the conditions under which the issue occurred and the original FEM model saved before meshing so that the reported errors can be reproduced. The Plug-in is distributed and available for use free of charge and does not include a support service; submitting a report does not guarantee a reply or assistance with the model.

The Plug-in was developed with the aid of AI-assisted programming tools, in particular OpenCode and ChatGPT. The original project code is distributed under GPL-2.0-or-later; third-party dependencies retain their own licences. The MESHing GitHub release page provides the latest version, corresponding sources and installation files.

Operating procedure

  1. Select model objects. Open a saved SAP2000/CSiBridge model. Select one or more areas, plus any joints and frames constraining the geometry. The selection can change while MESHing is open; Generate is enabled when at least one area is selected.
  2. Configure and generate. Choose mesh sizes and Gmsh settings, then press Generate. FAST checks the tables before modifying the model and does not silently switch to Standard insertion; verified CSV imports preserve polygon continuation rows in SAP2000/CSiBridge 27.1. The current SDB/BDB is saved before generation, whether or not the numbered backup is enabled.
  3. Review and continue. Inspect Mesh quality and the model. The completed-elements count and elapsed time remain visible below the commands until another area is selected. Undo mesh restores the state saved just before this generation. To keep the mesh, select an area for the next Generate or close MESHing. Generating again asks for confirmation before saving the current model and replacing the available Undo; the resulting mesh still needs an explicit host save to persist on disk.

Generate and Undo

Generate combines generation and application. In SAP2000 and CSiBridge with supported FAST tables, joints and shells receive their final numeric names and source areas are removed during Generate. If the FAST table check fails, Generate stops before insertion without changing methods. No Apply confirmation follows.

The optional numbered backup copies the previously saved SDB/BDB first. Generate then saves the current model before inserting the mesh; the mesh remains in memory until the user saves in the host. Undo mesh restores the state saved immediately before the latest Generate. Cancel generation also reopens that file when the current API call returns. If the saved file changes externally, Undo does not overwrite it and the private copy is retained.

After completion, Generate stays disabled until a model area is selected. A subsequent Generate asks for OK or Cancel and offers “Do not show this warning again in this session”: the current model will be saved, the previous generation will no longer have Undo, and Undo will refer only to the upcoming generation. The warning for disabled numbered backups is separate and unchanged. Closing MESHing asks for confirmation: Undo will no longer be available, while closing the unsaved meshed model without saving restores the on-disk state preceding the latest Generate.

Length units and numeric entry

A number without a suffix is interpreted in the current length unit shown beside the input box: for example, 100 in a field labelled (mm) means 100 mm. You may also type a unit explicitly with the number—m, cm, mm, ft or in—and the value is converted automatically into the effective length unit for the operation. Thus 0.1m, 10cm and 100mm specify the same physical length even when SAP2000/CSiBridge displays a different unit. This applies to Max Mesh Size, Min Mesh Size and Diameter; the minimum mesh size may be zero.

With SAP2000/CSiBridge 27.2 and later, the Plug-in may temporarily use the model's database units when calling the SAP2000/CSiBridge API and then restore the prior unit selection; always follow the unit shown in the Plug-in window. Dimensionless Gmsh settings such as minimum quality and iteration counts do not accept length suffixes.

Quality checks and internal settings

The quality window displays only the retained metric cards. Overall verdict, summary and scale legend are not shown there; sizing and validity checks still run when generating the mesh.

The former Tolerance control is absent from the current interface and does not govern generation. The Plug-in instead uses a fixed assessment policy, not a user setting: it reports elements whose free edges exceed 120% of the nominal target and evaluates the aggregate excess. The size check fails when affected mesh area exceeds 10%, area-weighted mean excess exceeds 2%, or an individual free edge exceeds approximately 1.5 times the nominal target. Protected original segments are reported separately. Shape and inverted or degenerate elements are checked independently; a successfully generated mesh can therefore carry quality warnings.

The backend also fixes settings required for first-order two-dimensional shells, including Mesh.ElementOrder=1, Mesh.MeshSizeFactor=1, size propagation from points and boundaries disabled, and Mesh.SubdivisionAlgorithm=0. These are not editable tab controls; the effective JSON can still be inspected in diagnostic traces; previously saved hidden overrides are ignored. There is no manual structured-surface or sizing-field configuration section.

Gmsh Full-Quad and BAMG: Full-Quad Simple/Blossom use even intervals on temporary Gmsh area-mesh guide curves; existing SAP2000/CSiBridge frame objects are neither cut nor renamed. Immutable selected edges are respected. If the chosen algorithm (notably BAMG on heavily constrained geometry) generates a nearly collinear triangle, the mesh is rejected before import with a short diagnostic. Select a different algorithm (for example 8 — Frontal-Delaunay for Quads) and Generate again; the Plug-in does not silently change an explicitly selected algorithm.

Additional options

hole and opening checkboxes use the same native checked appearance as Prefer regular. You may choose either option before creating its group; Generate will explain which group is missing. O-grid is cleared when circular holes are unchecked. Existing SAP2000/CSiBridge frame objects are not edited.

The tab presents grid preference, symmetry, circular holes and bounded openings in the order shown in the illustration. Every control fits in the standard-size window without scrolling; scrolling remains available if operating-system display scaling reduces the usable space.

Prefer regular (grid-aligned) mesh when possible
Off by default. Requests a regular Gmsh discretization on geometrically compatible surfaces. It does not impose alignment with the global coordinate system or shell local axes: constrained or incompatible patches can remain unstructured and contain triangles. Saved preferences retain the choice; Reset defaults clears it.
Enforce mesh symmetry about the following axes
The selector lists eligible axes detected from the selected geometry, including two perpendicular axes where available. Eligibility depends on boundary, constraint and hole compatibility; the accompanying text explains availability. The generated topology is checked for symmetry before transfer into SAP2000/CSiBridge.
Create circular holes around this group of joints
Choose a Point-object group and enter a positive diameter. A length unit may be entered directly in the box and is converted automatically, as described under Length units. O-grid, available when circular holes are enabled, creates radial quadrilateral sectors around the holes; otherwise the ordinary circular opening is discretized. Hole geometry must remain within the selected coplanar areas without impermissible intersections with other openings or constraints.
Create openings around the following group of frames and/or shells edges
The group identifies eligible frames or incident shell edges defining an opening boundary. Only recognized closed cells are removed; an open frame chain remains a geometric mesh constraint. Existing SAP2000/CSiBridge frame objects are not physically divided.

Edges with selected joints

Selection groups can contain unrelated points or frames; those are not applied as meshing constraints. Coincident SAP2000/CSiBridge joint labels remain separate unless they belong to the same actual mesh topology. A connected existing edge is recognized by a continuous chain of SAP2000 joint identities between its original endpoints, not by coordinates alone.

The second checkbox under Additional options, “Do not add nodes to edges with selected interior joints”, is off by default. When enabled, the intervals on SAP2000/CSiBridge area edges bounded by explicitly selected joints retain their existing stations, without inserting extra nodes. Only edges containing such selected intermediate joints are protected; other edges may still be subdivided. Where two selected areas share an edge, the discretization must remain conforming on both sides. The effective JSON represents this setting as preserveSelectedEdges=true.

This is a geometric constraint, independent of grid preference and of the size acceptance policy. A protected original interval may already exceed the requested maximum size: the Plug-in preserves its joints and reports the consequences for mesh quality instead of silently rediscretizing it. On an isolated SAP2000 copy of nTEST010, with seven selected boundary joints and a 0.20 m target, the preference yielded 38 quads and 9 triangles (47 shells) while protecting the affected edges; the quality report still requires review. Reset defaults clears the preference.

Backup options and property transfer

The Backup options tab has one checkbox, enabled by default: create a numbered copy of the previously saved SDB/BDB before each Generate. It does not contain unsaved edits. Generate saves those edits to the active file even with backup disabled; the existing disabled-backup warnings remain available. The private pre-mesh checkpoint used for Undo is separate from the numbered backup.

FAST insertion is always enabled when compatible tables support it, falling back to the established object API where required. Compatible source-area properties are transferred to the generated shells; optional property failures are reported for manual review. The generated mesh is not automatically saved to the SDB/BDB.
